# 写操作行为规范（唯一真源）

> 本文件是写操作的**完整行为规范**。`SKILL.md` 与 `agents/MyBMO.md` 只保留速记摘要并指向这里，
> 改规则只改这一处，避免三份文档各说一套。
>
> 适用对象：调用方（人）与执行方（Agent）都必须遵守。写操作会真花钱、真改别人账户，**不可逆**。

## 一、适用范围

以下三条路径**全部**受本规范约束，一条都不能跳过：

| 路径 | 示例 |
|---|---|
| `write` 全部子命令 | `write word-add` / `word-update` / `word-delete` / `campaign-update` / `adgroup-update` |
| 跨账户复制 | `transfer clone --execute` |
| 通用透传 | `call` 调写类方法（`addWord` / `updateCampaign` 等） |

换条命令不代表能绕过审批。

## 二、三步走

**第一步 预览**：不加 `--execute` 跑一次，拿到完整报文与 `approval.digest`。

```bash
uv run scripts/bmctl.py write word-add --adgroup-id 10086 \
  --words "月季,玫瑰花" --price 3.5 --phrase-type 2
# 输出里："approval": {"digest": "cfa5cd773f5bdf99", "confirm_card": {...}}
```

**第二步 确认**：预览输出里的 `approval.confirm_card` 就是现成的卡片内容——
标题、字段（账户 / 动作 / 条数 / 回执）、选项（确认执行 / 取消）、不可逆提示都在里面。
**原样弹给用户点选**，不要自己另写一段话代替，也不要省略字段。

不许只在正文里问一句"要不要执行"。正文提问的问题是：用户很容易没看清数字就回"可以"；
卡片把关键字段摆在同一屏，逼着看一眼再点。

用户选「取消」或改口，就停手——不要换个措辞再问一遍，也不要自己改参数"再试一次"。

**第三步 执行**：用户点了「确认执行」之后，才用那个 digest 加 `--execute --confirm <digest>`。

```bash
uv run scripts/bmctl.py write word-add --adgroup-id 10086 \
  --words "月季,玫瑰花" --price 3.5 --phrase-type 2 \
  --execute --confirm cfa5cd773f5bdf99
```

**环境不支持卡片时**（例如纯命令行里由人直接操作），退化为正文表格确认，
但必须逐项列出上述字段，且明确写出「确认后不可撤销」。

## 三、digest 是命令级强制

`--confirm` 不是礼节，是本地硬校验：

- 没有 digest → 说明没预览过 → 直接拒绝（退出码 4）
- digest 与当前报文不符 → 说明预览之后改了参数 → 也拒绝

所以「先给用户看，再写」不靠自觉。digest **只会出现在预览输出里**，
执行被拒时不会回显——别想从错误信息里抄一个。

**用户说"加进去吧"不等于同意跳过预览**，预览是你必须走的一步。

## 四、五条铁律

1. **永远三步走：预览 → 弹确认卡片 → 带 digest 执行。** 见上文。
2. **一次只做一件事。** 不要在同一条命令里既加词又改价。用户要改 5 个单元，
   就分 5 次预览 + 5 次执行，每次确认。
3. **报结果必须带 id 和数量。** 写完要说"已加 3 个词到单元 10086，返回 wordId 7001/7002/7003"，
   不能只说"已完成"。失败要说清是哪一级、哪个物料，不允许含糊成"部分成功"。
4. **尊重批量上限**：单次 200 词 / 20 计划 / 50 单元。超了会被本地拒绝——不要试图绕开，
   拆成多批，并告诉用户分几批跑。
5. **每次真实写入都落审计**：`~/.workbuddy/baidu-marketing/audit/YYYY-MM-DD.jsonl`，
   记录账户、物料、完整报文和审批 digest。出问题可按天回溯。

## 五、失败怎么判断

| 退出码 / 现象 | 含义 | 做法 |
|---|---|---|
| 4 +「需要用户审批」 | 没带 `--confirm`，或 digest 对不上 | 重新预览，用新 digest 执行，别跳过 |
| 3 +「需要投放管理权限」 | 权限域未开通（89406 已翻译） | 去开发者后台补权限并重新授权 |
| 5 +「写入中断」 | 写了一半失败（如建了计划却拿不到 id） | 立刻告诉用户账户里已留下什么，需手工清理 |
| 2 +「参数错误」 | 本地拦截：缺字段 / 超批量 / 空列表 | 按提示补参数，未发出任何请求 |
| 6 | 绕过了 uv，直接用 <3.9 的 python | 改用 `uv run`，别换参数重试 |
| 接口返回 81020 | userName 与令牌不属同一账户 | 用 `--account` 指定，别混用凭据 |

失败时**把 `code` / `hint` 原样转述**，不要自己改参数重试着"试出来"。
